## 方針
cad-core は「立体を作る核」のまま、小さく育てる。**核の既存の約束（stateless・JSON入力）は壊さない。** 地図は別モジュールとして足し、同じ JSON の流れに乗せる。

## フェーズ（それぞれ別 PR）
### P0：動く状態を固定する（小さい）
1. `pytest` が clone 直後にそのまま動くようにする（import の書き方、または `pytest.ini`/`conftest.py` の調整）。
2. GitHub Actions で push ごとに pytest（cadquery を入れる。時間がかかるのでキャッシュ）。
3. README を最新化（上の現状に合わせる。`README-session.md` の古い記述は消さず「古い」と明記）。

### P1：iPhone で使える入り口
- 軽い Web 画面（単一の `index.html`）：説明を日本語で入力 or サンプル JSON を選ぶ → `/api/build` → three.js で 3D 表示（回して見られる）。STL のダウンロード。
- API の接続先と token は設定画面で入れる（リポジトリに入れない）。
- 完了の条件：iPhone Safari で、サンプル（穴あきの箱）が表示され、指で回せる。

### P2：地図（三次元）＝ 新モジュール `core/terrain.py`
やりたいこと：等高線・標高データから、**地形の立体模型**を作る。
- 入力（JSON に `terrain` を足す）：
  - 方式A「等高線を積む」：各標高の閉じた等高線（座標の列）＋標高 → 層ごとに押し出して積み上げた段々の立体（3Dプリント・ペーパークラフト向き）。
  - 方式B「標高グリッド」：格子状の標高値（行列）→ 滑らかな地形メッシュ → 底を張って立体に。
- 出力：既存の `BuildResult` と同じ形（体積・面数・警告）＋ STL。
- 縮尺・垂直誇張（高さを何倍にするか）・底板の厚みを指定できる。
- データの出どころ（リンク方式。標高タイルの URL 形式は、このクラウドからは確認できていないので、最初に実際に開いて確かめる）：**国土地理院の標高データ（DEM）を、出典表示つきで使う案**。ただし取得先は GitHub Actions や本人の PC からになる（このクラウド環境からは外部サイトに届かない）。取得は別スクリプト（`tools/fetch_gsi_dem.py`）にして、核は「渡された配列だけを扱う」形に保つ。
- 完了の条件：小さな範囲（例：自宅周辺の 2km 四方）の標高から、STL が作れて、体積が 0 より大きく、`isValid()` が真。

### P3：占い・羅盤とのつながり（本筋・03 と同時進行で設計をそろえる）
- 羅盤（lopan）の方位盤を、地図の上に重ねる／風水の地形（龍脈・水の流れ）の見える化に使える。ここは Nori の意向を聞いてから。
