# GitHub エージェントへの指示書（下準備）　2026-10-24

## 使い方
- 1つのファイル = 1つの依頼（Issue の本文にそのまま貼れます）。**1回の依頼で、1つのリポジトリ・1つの目的**にします。
- 順番：**01 鍵の除去（5分）→ 02 自動テスト → 03 占いの統合（棟梁。大きい）→ 04 KAGI → 05 CAD**。
- どの依頼も共通の約束（下の「共通の約束」）を、先頭に付けて渡します。

## 共通の約束（毎回、先頭に貼る）
1. 作業は**新しいブランチ**で。`main` に直接入れない。マージは、人（Nori）が決める。
2. **ファイルを消すときは、消す前に一覧を出して**、その一覧を PR の説明に書く（履歴の書き換え `git filter-repo` / `push --force` は、しない）。
3. 鍵・トークン・パスワードの値は、コード・ログ・PR に**書かない**。見つけたら、場所だけ報告する。
4. 変更ごとに、動作を確かめる手順（コマンド）と結果を、PR の説明に書く。確かめられなかったことは「未確認」と書く。
5. 日本語で、やさしく短く。専門語には一言の言い換えを付ける。
6. アプリは「単一ファイル HTML の PWA」を基本にする。ビルドツール・フレームワークを新しく足さない（今あるものは壊さない）。
7. PowerShell の例は、貼ってそのまま動く形（穴あきにしない・`} else {` を同じ行・複数行は `& { … }`）。
8. 既存のテスト・動くものを**壊さない**。壊れたら、元に戻して報告する。

## ここで決めてあること（Nori の回答）
- リポジトリは**公開のまま**にする（有料化のため）。秘密の鑑定文書は「読まれても構わない」とのこと。ただし、**他人の文章・写真（教科書のページなど）は、公開に向かないかもしれない**ので、PR で「著作権の確認が要るファイル」として一覧にする（消さない）。
